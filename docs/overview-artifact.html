Community Post Agent

Telegram · X · Reddit · LinkedIn 네 섹션에 맞는 글과 JPG / GIF / MP4를 폴더 하나로 만듭니다. 한 주제를 네 곳에 한 번에 뿌릴 수도, 플랫폼 하나만 따로 돌릴 수도 있습니다. 검토 후 직접 올리고, 자동 포스팅은 2단계에서 붙입니다.

LLM이 하는 일 (글, 컨셉, 리뷰) 코드가 하는 일 (검증, 렌더링, 패키징) 사람이 하는 일 (브리프, 검토, 업로드)
00 / 실행 모드

같은 주제로 한 번에, 또는 플랫폼 하나만 따로

네 플랫폼은 각각 독립 섹션입니다. 브리프의 platforms에 적은 만큼만 돌고, 폴더도 그만큼만 생깁니다.

CAMPAIGN

한 주제 → 선택한 N개 플랫폼

릴리즈 공지처럼 같은 메시지를 여러 곳에. Planner가 플랫폼별 앵글을 나누고 숫자·주장을 일치시킵니다.

# briefs/v2-release.md platforms: [telegram, x, reddit, linkedin] $ community run briefs/v2-release.md $ community run briefs/v2-release.md --platform x,reddit → output/2026-11-03_v2-release/{telegram,x,reddit,linkedin}/
SINGLE

플랫폼 하나, 그곳만의 주제

X 전용 개발 팁, Reddit 전용 기술 후기처럼 다른 곳엔 안 올릴 글. 브리프가 짧고 Planner도 가볍게 돕니다.

# briefs/x-dev-tip-013.md platforms: [x] $ community run briefs/x-dev-tip-013.md → output/2026-11-03_x-dev-tip-013_x/
BATCH

서로 다른 주제 여러 개를 한 번에

브리프 폴더를 통째로. 각 브리프는 위 두 모드 중 하나로 독립 실행되고 끝에 요약 한 장이 붙습니다.

$ community run briefs/*.md → output/.../ ×4 + BATCH_SUMMARY.md
01 / 어떻게 진행되나

브리프 1개가 7단계를 지나 4개 플랫폼 패키지가 됩니다

LLM은 글과 미디어 컨셉만 쓰고, 글자 수·해시태그·파일 규격 같은 하드 제약은 코드가 검사합니다. 위반하면 에러 목록을 붙여 다시 쓰게 합니다.

03 / 내가 어떻게 쓰나

브리프 쓰기, 한 줄 실행, REVIEW.md 열기, 복붙

하루 운영 흐름입니다. 사람이 손대는 지점은 처음(브리프)과 끝(검토·업로드) 두 곳입니다.

STEP 1 · 브리프

예시를 복사해 채웁니다

제목, 핵심 사실 불릿, 피해야 할 표현, 첨부 파일 경로, 플랫폼별 메모. 5분 안에 끝나는 양입니다.

$ cp brief.example.md briefs/2026-11-03_v2-release.md $ vim briefs/2026-11-03_v2-release.md
STEP 2 · 실행

명령 한 줄, 1~3분

LLM 호출 6~8회, 미디어 렌더 포함. 진행 상황과 비용이 터미널에 표시됩니다.

$ community run briefs/2026-11-03_v2-release.md ✓ plan 2.1s ✓ write ×4 9.4s (x: 1 retry — 288 > 280) ✓ media 5 jobs 31s ✓ review 3.0s → output/2026-11-03_v2-release/REVIEW.md ($0.41)
STEP 3 · 검토

REVIEW.md 한 장을 봅니다

4개 글, 글자 수, 미디어 썸네일, 리뷰 점수와 제안이 한 화면에. 마음에 안 드는 플랫폼만 다시 씁니다.

$ community rewrite output/2026-11-03_v2-release \ --platform x --note "숫자를 첫 문장에" $ community render output/2026-11-03_v2-release --only gif
STEP 4 · 업로드

플랫폼마다 정해진 파일을 복붙

아래 표의 파일을 열어 붙이고 미디어를 첨부합니다. 2단계에서는 이 자리에 community publish가 들어갑니다.

04 / 구현 순서

텍스트부터 돌아가게 하고, 미디어를 한 종류씩 붙입니다

각 단계가 끝날 때마다 실제 브리프로 한 번 돌려 결과를 보여드리고, 프롬프트와 템플릿을 같이 조정합니다.

PHASE 1

텍스트 파이프라인

  • 브리프 파서, Planner, Writer ×4
  • Validator + 재시도
  • REVIEW.md (텍스트만)
PHASE 2

JPG

  • 템플릿 6종 (HTML/CSS)
  • Playwright 렌더, 플랫폼별 해상도
  • 첨부 이미지 크롭·로고
PHASE 3

GIF · MP4

  • 프레임 → GIF + MP4 쌍둥이
  • 슬라이드 + 자막 번인 MP4
  • 용량·길이 자동 축소
PHASE 4

Reviewer · 재생성

  • Reviewer 호출, 점수 표
  • rewrite / render --only
  • 비용 로그
PHASE 5 · 나중

자동 포스팅

  • Telegram Bot, X API, PRAW, LinkedIn
  • publish 승인 플로우
  • 성과 지표 → 다음 브리프 반영
05 / 시작 전에 확인해 주세요

이 셋만 정해지면 Phase 1을 바로 시작합니다

포스트 기본 언어

현재 가정: Telegram 한국어, X·Reddit·LinkedIn 영어. 브리프마다 바꿀 수 있지만 기본값이 맞는지.

이미지 소스

현재 가정: HTML 템플릿 카드 + 첨부한 스크린샷. AI 이미지 생성은 나중 플러그인. 처음부터 AI 생성이 필요하면 Phase 2에 포함.

브랜드 자료

로고 PNG, 폰트, 색상 2~3개를 assets/와 config/brand.yaml에. 없으면 플레이스홀더로 먼저 진행.

디자인 톤앤매너 (Mobbin · Cloud Studio)

지정해 주신 Mobbin 페이지는 로그인 뒤에 있어 열 수 없었습니다. 화면 캡처 3~5장을 assets/reference/에 넣어 주시면 색·타이포·여백·라운드 값을 뽑아 brand.yaml과 이미지 템플릿에 반영합니다.
